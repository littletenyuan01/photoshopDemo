## 它不是"示意图"

页面里跑的是**真实的像素数组**，所有数字都是当场算出来的：

| 页面上的东西 | 真实实现 |
|---|---|
| 每个图层一套稀疏格子集合 | `Map<layerId:tx,ty>` → `Float32Array`（预乘 RGBA） |
| **划分 ≠ 分配** | 寻址空间由尺寸推导（`⌈宽/边长⌉ × ⌈高/边长⌉` 个**地址**）；**数据块**只在写像素时惰性分配（`ensureTile`）。新建透明文档：12 个地址、**0 个数据块** |
| **边缘瓦片** | 划分只覆盖文档范围，所以**上取整**：最后一行/列可能只用得到一部分（400×300 + 粒度 128 → 右列有效宽仅 16px、下行仅 44px）。**画布外没有瓦片**；不满一格仍**按整块占内存** |
| 合成公式 | `out = src + dst × (1 − srcA)`，自底向上逐像素 |
| 只重算脏格子 | `recompute()`：按待重算集合，或被"整幅对照"模式覆盖 |
| 历史按区域存 | 一次操作前快照**被触碰的那几块**的旧内容 |
| 暂存盘换页 | LRU：超额度就把最久未用的格子标为"在磁盘"，再用时换入 |
| 缩放缓存级别 | L0/L1/L2（100%/50%/25%），级别的格子覆盖更大图像范围 |

**有意简化并如实标注的地方**：颜色运算内部用 float32（便于看数值），
而"存储字节"按位深算（8 位 = 4 B/px，16 位 = 8 B/px）；金字塔是从 L0 现场降采样，
不是像 PS 那样预先/惰性维护多级缓存。

## 资料分级（页面上逐条标注）

  8/16/32 位管线、图层可小于画布带偏移、图层组。
- **[共识]** 长期被业界引用、但 Adobe **未文档化**的实现数字：
  最典型的就是 **128×128 瓦片**。页面上不会把它说成官方定论。
- **[源码]** GIMP 开源，可逐条核对：
  `app/gegl/gimptilehandlervalidate.c`（按 tile 惰性渲染）、
  `app/core/gimpprojection.c`（脏区 → 瓦片失效）、
  `app/core/gimpdrawableundo.h`（`GeglBuffer + x/y/w/h` 的区域撤销）、
  `GimpGroupLayer`（图层组）、瓦片边长是**可配属性**（历史默认 64×64）。

## 9 个步骤在讲什么

1. **新建文档**：建立的是**元数据 + 一条图层记录**；格子只是"按粒度推导出的**寻址空间**"
   （`⌈宽/边长⌉ × ⌈高/边长⌉` 个地址），不是被创建出来的对象。透明底时**地址有、数据 0 字节**。
2. **瓦片是什么**：先"划分"（寻址）后"分配"（写像素才申请内存）；坐标换算 `tx=⌊x/边长⌋`、
   稀疏分配、**边缘瓦片**（右/下不满一格也占一整块，切「400×300」按钮看）、
   以及"为什么非要瓦片"的 7 个理由；切 64/128/256 看同一笔触碰格子数的变化。
3. **新建图层**：又一套**空的**寻址空间（+ 偏移）；隐藏层仍占存储；图层表是**顺序表不是链表**，
   只有图层组是树。
4. **操作图层**：写瓦片（惰性分配）→ 标脏 → 合成缓存对应瓦片失效 → 只重画那几块；
   不变量是"只碰活动层"。
5. **你看到的画面**：合成缓存（第三份数据）+ 缓存级别金字塔 + 只光栅化视口。
6. **撤销/历史**：按改动区域存（对比"整幅快照"的代价：4000×3000 每步 48 MB）。
7. **暂存盘**：拉小内存额度，看瓦片变橙（换出）→ 再访问时换入（磁盘 IO 的来源）。
8. **PS 与 GIMP 对照表**：逐条标官方/共识/源码。
9. **总结**：一次"画一笔"的完整链路（8 步）+ 三句话记住整套设计。

## 自检（可选）

`_verify/run_in_node.js` 用最小 DOM 桩件把 `app.js` 真跑一遍，验证 12 条结论：

```
node _verify/run_in_node.js
```

实测输出（节选）：

```
新建透明文档：已分配瓦片 = 0（像素内存 0 字节）
一笔只触碰 3 块瓦片（≤4）
脏瓦片模式重算 1 块 / 整幅 12 块
边长 64 触碰 13 块 > 边长 256 触碰 3 块
白底 + 50% 红 = [1.00, 0.50, 0.50, 1.00]（期望 1, 0.5, 0.5, 1）
隐藏后合成结果是纯白，但该层仍有 4 块瓦片
一步历史 = 1 块 × 64 KB = 64 KB（整幅快照 768 KB）
撤销把该区域还原（alpha 1.00 → 0.00）
换出 26 块后，内存占用 1024 KB ≤ 额度 1 MB
```

> 说明：`_verify/` 是**自检脚本**，不是演示稿运行时依赖；删掉它不影响页面。
> 它已经抓出过两个真 bug：局部变量 `rows` 遮蔽网格行数函数导致的启动崩溃（页面会全白），
> 以及"历史记录存的是画完之后的数据、撤销等于没撤"。
