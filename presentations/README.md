# 演示稿库（presentations）

> 每一份演示稿一个子目录，双击该目录下的 `index.html` 即可打开。
> 也可以先打开本目录的 [`index.html`](index.html) 作为入口页。

## 目录约定

```
presentations/
  index.html                     入口页：列出所有演示稿（新增文稿时在这里加一张卡片）
  README.md                      本文件：约定 + 索引
  01-photoshop-image-engine/     一份演示稿 = 一个目录
    index.html                   入口（双击即开，离线，无外部依赖）
    app.js                       演示逻辑（真实数组/真实计算，不是示意图）
    style.css                    外观（沿用 psDemo 深色配色，见 resources/styles/dark.qss）
    README.md                    这一份讲什么、怎么自检、有哪些简化
    _verify/                     可选自检脚本（不影响页面运行）
  02-xxx/                        …后续文稿
```

**命名**：`NN-主题`（两位序号 + 短横线 + 英文短名）。序号决定入口页里的顺序；
主题用 kebab-case，别用中文目录名（避免跨平台/命令行编码问题）。

**每份文稿的硬要求**（沿用 01 立的规矩）：

1. **离线自足**：不引用 CDN / 外链资源，双击就能开；
2. **数字必须当场算出来**，不是抄的；算不了的就明确写成"引用/估计"；
3. **资料分级标注**，避免把传言当定论：
   - `[官方]` 官方文档/源码里能查到的
   - `[共识]` 业界长期引用但未文档化的（例如 PS 的 128×128 瓦片）
   - `[源码]` 有开源实现可逐条核对的（本项目常用 GIMP，见 `gimp-master/`）
   - `[模拟]` 演示稿自己的简化，必须说明简化在哪
4. **可自检**：把"文稿声称的结论"写成断言脚本放进 `_verify/`，
   `README.md` 里写清跑法与实测输出。**不能用"看起来对"当验证**。

## 写文稿时的体例

1. **一步只说一件事**：简明版每步 ≤4 行字 + 1 个示范按钮；内容多了就拆成一份新的深入版，
   不要往同一页里塞；
2. **默认界面上控件 ≤ 4 组**，进阶参数收进深入版；
3. 每步都要能"点一下就动"（示范按钮），不让读者先摸索控件；
4. 数字当场算、资料分级标注、配 `_verify/` 自检 —— 见上面「每份文稿的硬要求」。
