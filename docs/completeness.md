# 怎样才算「完善」（相对你已列的功能）

你已点名：图层、选区、蒙版、调整层、通道、画笔（钢笔）。  
这些是**编辑能力**；要算「完善的可演示图像软件」，还需要下面几类——多数是**基建与闭环**，不是再堆一堆花哨工具。

口径分两档：

- **完善（简历 Demo）**：链路自洽、能演示、能讲清架构  
- **产品级完善**：接近业余修图够用（仍远低于 PS）

---

## 1. 没有它们，上面功能等于不可用（P0 基建）

| 能力 | 为什么算基础 | 最低标准 |
|------|--------------|----------|
| 文档模型 | 图层/选区/历史都挂在文档上 | 新建、关闭、多文档或至少单文档清晰 |
| 画布显示 | 合成结果要看得见 | 缩放、平移、适应窗口；棋盘格表示透明 |
| 撤销/重做 | 编辑软件标配 | 绘制、图层、选区、蒙版、调整均可回退 |
| 打开/导出 | 闭环出口 | 打开常见位图；导出 PNG/JPEG（合成结果） |
| 主界面壳 | 工具要有入口 | 菜单 + 工具栏 + 图层面板 +（选区/蒙版状态） |
| 活动对象 | 否则不知画在哪 | 当前文档、当前图层、当前工具、选区是否存在 |

> 你列的「图层/画笔…」依赖这些；缺任一环都不算完善。

---

## 2. 让「编辑」真正像样的配套（P0～P1）

| 能力 | 说明 |
|------|------|
| 图层基础操作 | 不只显隐透明度：新建/删除/复制、排序、重命名；可选简单混合（Normal + 两三种） |
| 选区配套 | 取消/反选/全选；选区约束画笔与填充；可选羽化 |
| 填充与清屏 | 前景色填充、Delete 清选区；颜色选取（前景/背景） |
| 橡皮与硬度 | 与画笔成对；软硬边、不透明度、大小 |
| 合成正确性 | 透明度棋盘格、Alpha 合成顺序正确（含蒙版相乘） |
| 简化调整 | 色阶/曲线或简化调整层；至少能演示「非只靠涂抹改图」 |

通道面板、钢笔路径：**不是**「完善 Demo」的必需，见 `scope-estimate.md`。

---

## 3. 有了会像「软件」而不是实验代码（P1）

| 能力 | 说明 |
|------|------|
| 工程保存 | 自有格式保存图层+蒙版（或简单 JSON/二进制）；否则只能导出扁图 |
| 变换 | 移动、缩放、旋转当前层或选区（哪怕只有移动+缩放） |
| 裁剪 | 裁剪画布/图像大小 |
| 导航 | 缩略图/导航器可选；至少滚轮缩放 + 空格拖拽 |
| 快捷键 | 常用：撤销、笔刷大小、显隐层、取消选区 |
| 状态栏 | 坐标、缩放比、当前工具/层名 |

---

## 4. 产品向「够用」才需要、Demo 可后置（P2）

文字工具、渐变、形状、仿制图章、修复、滤镜库、历史面板细粒度、完整色彩管理、CMYK、动画、动作批处理……

这些会迅速膨胀代码量，**不作为本项目完善标准**。

### 已记录的 stretch（有余力再做）

下列三项已写入 `wiki/Roadmap.md` Phase 5，**可选、不阻塞完善标准**：

1. PSD 导入 / 导出（简版分层，非完美兼容）
2. 智能对象（嵌入 + 再栅格化，非 PS 全套）
3. 插件库（极简扩展点，非 PDB/完整宿主）

---

## 5. 完善度清单（建议自测）

### Demo 完善（推荐达标线）

- [ ] 新建/打开 → 多层编辑 → 选区限制绘制 → 蒙版抠图感 → 调整色调 → 撤销 → 导出  
- [ ] 透明区域棋盘格显示正确  
- [ ] 图层面板与画布始终一致  
- [ ] 无 GPU/无 CUDA 也能跑通上述链路  
- [ ] `docs/` 能对应到真实实现（不夸大）

### 产品向再加

- [ ] 保存/打开自有工程（含图层）  
- [ ] 移动/缩放变换、裁剪  
- [ ] 常用快捷键与基础颜色面板  

### 明确不算本项目「完善」必需

- [ ] 通道面板、钢笔路径、完整调整层全家桶、滤镜商城、PSD 完美兼容  

---

## 6. 一句话

**完善 = 你点名的编辑能力 + 文档/画布/历史/IO/界面壳 + 选区与颜色等配套，并形成一条可重复演示的闭环。**  
不是把 GIMP 里 widgets/display/plugins 那几十万行都做完。
