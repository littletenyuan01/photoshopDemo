# 滤镜现状与开发计划（含优先级评估）

> 口径：本文只谈**「滤镜」菜单**下的算子。菜单项取自 `psDemo/mainwindow.ui` 的 `menuFilter` 段，
> 接线状态取自 `psDemo/mainwindow.cpp` 里对每个 `action*->setEnabled(true)` 的实际调用 ——
> **不看计划、不看注释，只看代码里真的接上没有**。
>
> 统计时间：本次提交。**共 68 项菜单项，已接线 14 项，未做 54 项。**

---

## 1. 一句话结论

已做的 14 项覆盖了「模糊 / 锐化 / 杂色 / 其它」四类的骨干，且已建立**算子模板**
（`FilterOp` 三段式 + 注册表 + 参数页 + 菜单 + oracle 用例）。
剩下 54 项里：

- **8 项几乎零成本**（纯复用现成算子）；
- **9 项几何重映射**能把刚做完的 ROI 逐块机制压到极限，**性价比最高**；
- **21 项**是常规新算子，套模板即可；
- **13 项**不是「滤镜链」语义（生成式 / 交互式 / 需预设系统 / 专业校正），**建议不做**；
- **1 + 2 项**属于清理（模型里没有对应物 / 疑似占位符）。

## 3. 优先级怎么定的（判断标准先写清楚，避免拍脑袋）

| 维度 | 说明 |
|---|---|
| **成本** | ① 纯复用现成算子 < ② 加一个算子（套模板）< ③ 需要新参数类型 / 新通道 < ④ 需要新机制（交互、预设、生成器） |
| **收益** | 日常使用频率（模糊/锐化/杂色远高于渲染类） |
| **风险** | 是否引入**新概念**。本项目已经踩过的两类坑：**位置相关**（噪声那种 `(x,y,seed)` 依赖 → 必须整层求值）、**几何重映射**（输入区不等于输出区）。新算子若落在这两类里，要复用现成机制而非另造 |
| **验证成本** | 有数学定义 ⇒ 可写朴素 oracle（便宜）；无参考实现（如油画、光照）⇒ 只能人眼看（贵） |

**一条硬纪律**：任何新算子必须带**朴素 oracle 用例** + **分块投影 == 整幅合成**断言
（这是本项目抓出 3 个块界 bug 的那条护栏，见 `pending-dev.md` 缺陷台账 #16/#20）。

## 4. 分档与建议批次

### 批次 A —— 纯复用，**共 8 项**（预计最省，建议先做）

| 项 | 实现 | 成本 |
|---|---|---|
| 模糊 | 盒模糊 r=1 | ① |
| 进一步模糊 | 盒模糊 r=2 | ① |
| 锐化 | 现有锐化算子强度=1 | ① |
| 曝光过度 | 新增点算子：`v>128 ? 255-v : v` | ①（点算子 ~10 行） |
| 去斑 | 中值 r=1 | ① |
| 减少杂色 | 中值 + 强度混合 | ①（点+面积组合） |
| 蒙尘与划痕 | 中值 + 阈值（差超阈值才替换） | ② |
| 锐化边缘 | Sobel 幅值当 mask，只锐化边缘 | ② |

**验收**：`锐化`/`模糊` 与现有算子逐像素一致（复用同一实现就该一致）；其余各带 oracle。
**为什么排第一**：8 项里 5 项是「换参数调现成算子」，能把菜单从 14 项补到 22 项，且不引入任何新概念。

### 批次 B —— 几何重映射，**共 9 项**（性价比最高，建议紧随其后）

置换、挤压、极坐标、波纹、切变、球面化、旋转扭曲、波浪、水波

**为什么这批特别值**：它们都是「拉取型重映射」`out(x,y) = in(f(x,y))`，f 连续
⇒ **需要的输入区是 `f(输出区)` 的包围盒，仍是单矩形** ⇒ 正好走刚做完的
**逐块路径**（`FilterNode::requiredInputs` 再加一个分支即可），**不需要整层求值**。
这批做完等于给「任意重映射能进滤镜链」这件事做了一次压力验证。

**共同风险**：f 的雅可比可能 > 1（拉伸），包围盒会放大 —— 需要断言
「分块投影 == 整幅」，且要留意放大倍数过大时退化为整层更划算（实测后写进文档）。

**验收**：每项一个 oracle（用独立实现的朴素映射逐像素比对）+ 分块投影一致性 + 参数往返。

### 批次 C —— 常规邻域算子，**共 12 项**

径向模糊、表面模糊、特殊模糊、形状模糊、智能锐化、马赛克、碎片、等高线、风、拼贴、镜头模糊、凸出

**共同点**：都是「一个新算子 + 一个参数页」，套模板；每个 15–25 分钟。
**排后**是因为收益递减（使用频率低于 A/B），且镜头模糊 / 凸出偏重。

### 批次 D —— 确定性随机类，**共 5 项**

晶格化、点状化、铜版雕刻、扩散、油画

**必须复用**「添加杂色」那套：噪声 = `(x, y, seed)` 的纯散列函数（不保存噪声位图、可复现），
且它们是**位置相关算子** ⇒ 走整层路径（机制现成，见 `FilterStack::hasPositionalOp`）。
**排最后**是因为它们同时吃「位置相关」与「随机可复现」两个约束，是验证成本最高的一档。

### 批次 E —— 不做（**明确记录理由**），共 13 项 + 1 项

| 项 | 不做的理由 |
|---|---|
| 云彩 / 分层云彩 / 纤维 / 镜头光晕 / 光照效果 | **它们没有「输入图」这个概念**，本质是生成器。硬塞进滤镜链会让「滤镜 = 对图层做变换」这个语义变浑；要做应该另开「生成图层 / 填充」通道 |
| 液化 / 消失点 / 模糊画廊 | **交互式工具**，需要画布上的实时拖拽与局部网格，不是「非模态参数对话框」模型 |
| 滤镜库 | 需要**预设系统**（一堆滤镜的预设浏览器），是另一个子系统 |
| Camera Raw / 自适应广角 / 镜头校正 | 专业校正管线，属于另一条产品线 |
| 浏览滤镜 | 在线内容服务，与本地引擎无关 |
| 转换为智能滤镜 | **我们的滤镜本来就是非破坏的**（栈式、可开关、可撤销），没有「转」这个动作 |

### 批次 F —— 待确认 / 清理，**3 项**

| 项 | 处置 |
|---|---|
| `actionFilterDistort`（扭曲子菜单内） | PS 无此项，疑似占位符 → **确认后删除**或补实现 |
| `actionFilterNoise`（杂色子菜单内） | 与「添加杂色」重复，疑似占位符 → 同上 |
| `actionLastFilter`（上次滤镜操作） | 价值中等（重复上次滤镜），需要记「上次的 op + 全部参数」；我们已有完整参数序列化（`.pslite`），成本不高 → 可放批次 C |

## 6. 每批的通用交付清单（模板）

1. 算子：`engine/op/<name>filterop.{h,cpp}`（或并入 `filtereval.cpp` 的点算子表）；
2. `OpName` 追加到 **`Count` 之前**（`.pslite` 存的是枚举整数值，插中间会让旧文件错位）；
3. `FilterNode` 加参数字段 + `inputPad()`（面积算子）或 `requiredInputs()` 分支（几何）；
4. `opsinit.cpp` 注册（有临时资源的走 `FilterOp`；纯点算子走 `applyPointNode` 直接分发）；
5. `.pslite` 参数按**尾部追加**写入（固定块布局，勿动已有顺序）；
6. 参数页（`adjustmentpropshost.cpp`）+ 菜单接线（`mainwindow.cpp`）；
7. 测试：朴素 oracle + **分块投影 == 整幅** + 参数往返；
8. 文档：`features.md`（能力清单）、`tests.md`（用例表）、`pending-dev.md`（本轮留痕 + 缺陷台账）；
9. `app.pri` / `tests.pro` 登记新文件。

> 这条模板已经跑过 5 轮（自定滤镜、最大值/最小值、高通、运动模糊、添加杂色），
> 实测**每个算子 15–25 分钟**（含构建与用例），见 `dev-plan.md` §5.1 的构建成本实测。
