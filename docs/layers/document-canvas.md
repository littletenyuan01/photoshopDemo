# 文档、画布与图像大小

## 1. 文档是什么

**文档**（本项目 `ImageDocument`，GIMP 的 `GimpImage`）是内存里一份「可编辑图」的根对象：

- 宽高（像素）
- 图层栈、活动层
- （完整 PS 还有分辨率、颜色模式等；本 Demo 新建时 PPI 主要用于 mm→像素换算，尚未作为文档字段持久化）

界面上的画布、图层面板都是**观察这份文档**，像素真相在文档的图层里，不另存一份。

新建文档（如 A4 @ 300 PPI、白底）本质是：算出像素宽高 → 创建文档 → 加一层白色背景 → 交给会话广播 → 视图刷新。  
此时通常**还不写磁盘**。

## 2. 文档 ≠ 画布 ≠ 视图

| 名称 | 含义 |
|------|------|
| **文档** | 数据：尺寸 + 多层像素 |
| **背景层** | 文档里第一层像素（常见为白底）；口语里常被叫「白画布」，程序里是一层 `Layer` |
| **画布（口语）** | 中间能编辑的那块工作范围，即文档的宽高范围 |
| **视图**（`CanvasView`） | 窗口里的显示器：缩放、平移，把合成结果画到屏幕上 |

类比：文档像文件本身；视图像打开文件的窗口。滚轮放大缩小改的是**视图**，不改文档像素数。

GIMP 对应：`GimpImage`（文档）+ `GimpDisplay` / Display Shell（视图）。新建时先 `gimp_image_new_from_template`，再 `gimp_create_display`。

## 3. 分辨率（PPI）是什么

单位已是**像素**时，真正决定图像大小的是宽×高像素数；PPI **不会再多造像素**。

PPI 表示：这些像素按多密对应到物理尺寸（打印）。

\[
像素边长 \approx 物理边长（英寸）\times PPI
\]

例如 A4（约 210×297 mm）@ 300 PPI ≈ **2480×3508** 像素。  
单位改成 mm/cm 时，要用 PPI 把物理尺寸**换算成**像素；单位已是像素时，PPI 主要是元数据（打印用）。

## 4. 视图 100% ≠ 物理打印纸面大小

- **100%**：图像 1 像素 ↔ 屏幕 1 像素（显示比例）
- **物理大小**：像素数 ÷ PPI（打印/标尺意义）

同一张图在不同显示器上 100% 占的厘米数可以不同；按 300 PPI 打印才接近 A4。

缩放不虚：放大视图多半是把像素画成更大色块（或有限插值），**没有**改文档分辨率；真要用「图像大小」重采样放大，才会变糊。

## 5. 图像大小 vs 画布大小（PS 菜单）

| | **图像大小** | **画布大小** |
|--|--------------|--------------|
| 改什么 | 像素总数和/或 PPI | 文档工作台宽高（加边/裁边） |
| 图层内容 | 通常重采样缩放 | 默认不缩放，只加空白或裁切 |
| 比喻 | 把照片冲印得更大/更小 | 换更大/更小的纸，照片本身不动 |

本 Demo 已接线：

| 菜单 | 对话框 | Domain |
|------|--------|--------|
| 图像 → 图像大小… | `ui/imagesizedialog.ui` | `ImageDocument::scaleImage`（勾选「重新采样」时） |
| 图像 → 画布大小… | `ui/canvassizedialog.ui` | `ImageDocument::resizeCanvas`（锚点 + 扩展色） |

未勾选重新采样时像素不变（PPI 尚未写入 domain）。

## 6. 本项目新建后实际有什么

以 A4 @ 300、白底为例（像素约 2480×3508）：

1. `ImageDocument`（宽高）
2. 一层 `Layer`「背景」：`TileBuffer` + `fill(白)`（覆盖瓦片均已分配并填白）
3. `AppSession::setDocument` 广播；`CanvasView` 等订阅刷新

图层面板再「新建」一层时，仍走同一套 `Layer(extent)`，只是不 fill → 0 块瓦片。见 [tiles-and-memory.md](tiles-and-memory.md)。

**不会**单独 new 一个「画布数据对象」；中间窗口是已有视图开始显示新文档。
