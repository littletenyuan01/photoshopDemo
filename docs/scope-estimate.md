# 功能范围评估：图层 / 选区 / 蒙版 / 调整层 / 通道 / 画笔·钢笔

评估口径：对照 GIMP 实现体量 + 本项目约束（Qt Demo、≤约 7 万行、简历可讲、链路完整）。  
GIMP 数字为相关目录 `.c/.h` 粗测（含空行注释），**不含 GEGL 库本身**。

## 总判断

| 功能 | 算不算「图像软件基础」 | 建议纳入本项目？ | 说明 |
|------|------------------------|------------------|------|
| 图层 | **是（核心）** | **必做** | 没有图层就谈不上仿 PS |
| 选区 | **是（核心）** | **必做（简版）** | 编辑边界的基础 |
| 蒙版 | **是（核心）** | **强烈建议** | 与图层强绑定，简历亮点 |
| 调整图层 | **是（PS 叙事基础）** | **做简化版** | GIMP 也无 PS 式一等调整层 |
| 通道 | **偏进阶面板** | **可砍或极简** | 选区/蒙版内部用灰度即可 |
| 画笔 | **是（核心）** | **必做** | 像素写入主路径 |
| 钢笔（路径） | **进阶矢量工具** | **建议后置/砍** | 体量大，非 v1 必需 |

**一句话**：你列的多数是「修图软件叙事里的基础」；其中 **通道面板、钢笔** 更偏完整版能力。全部按 PS/GIMP 完整度做，会轻松摸到甚至超过 7 万行上限。

## 与 GIMP 的体量对照（帮助建立直觉）

| 功能 | GIMP 相关粗 LOC | 完整版含义 | 本项目 MVP 含义 |
|------|-----------------|------------|-----------------|
| 图层 + 混合模式 | ~20k | 组层、几十种模式、投影管线 | 扁平栈 + 透明度 + 3～5 种混合 |
| 选区 | ~20k | 智能选区、浮选、复杂布尔 | 矩形/椭圆/套索 + 约束绘制 |
| 蒙版 | ~1k+依赖 | 滤镜蒙版、组蒙版、通道互通 | 每层一张灰度蒙版 + 黑白涂抹 |
| 调整（滤镜） | ~19k | 非破坏滤镜栈 / GEGL | 色阶+曲线；或「假调整层」 |
| 通道 | ~4k | 用户通道面板、通道运算 | 可不做面板 |
| 画笔体系 | ~28k+ | 动力学、克隆修复、MyPaint | 圆笔软硬、画笔/橡皮、不透明度 |
| 钢笔/路径 | ~22k | 贝塞尔编辑、描边、选区互转 | 建议不做；或折线→选区 |

七块在 GIMP 里粗加约 **11～12 万行**（仅切片）；真完整还要 UI/撤销/GEGL。

### 关于「调整图层」

GIMP **没有** Photoshop 那种一等 Adjustment Layer，而是 **Drawable Filter + GEGL**。  
本项目若写「调整图层」，推荐两种之一：

1. **破坏式调整**：对当前层直接做色阶/曲线（实现快）  
2. **简化调整层**：一种特殊层，合成时对**下方合并结果**做色调运算（简历更好讲，代码量中等）

不要追求 PS 全套调整层类型与完整非破坏栈。

### 关于「钢笔」

若指 **钢笔路径工具（Pen/Path）**：是矢量编辑，复杂度接近又一个子系统。  
若指 **画笔里的硬边笔/铅笔**：属于画笔参数，工作量很小。  
下文「钢笔」按 **路径工具** 理解。

单位：人周（按单人业余/课余认真开发理解，含联调与文档）；代码量为 **本功能相关新增** 的粗估（含 `.h/.cpp/.ui`，不含第三方库）。

| 功能 | 难度 | 预估人周 | 预估代码量 | 优先级 |

| 画笔 + 橡皮（含压感可选） | 中 | 1.5～2.5 | 3～6k | P0 |

### 打包情景

| 情景 | 包含 | 合计代码量（约） | 合计人周（约） | 与 7 万行关系 |
|------|------|------------------|----------------|----------------|
| **A. 简历闭环（推荐）** | 基建+图层+画笔+选区+蒙版+简化调整 | **18～35k** | **11～18** | 舒适，留余量 |
| **B. 你点名的全套简版** | A + 通道面板 + 极简路径 | **28～48k** | **16～25** | 仍可，时间紧 |
| **C. 追 GIMP/PS 完整度** | 上表全做深 | **50k～70k+** | **30+** | 易爆、难讲清 |

推荐走 **情景 A**，通道与钢笔写进「后续工作」；面试时能讲清合成、蒙版、选区约束、调整层模型即可。

## 建议落地顺序

```text
1. Document + Canvas + 撤销 + 打开导出
2. 图层栈 + 合成（Normal/透明度）+ 图层面板
3. 画笔 / 橡皮（受活动层约束）
4. 选区（再让画笔只画选区内）
5. 图层蒙版
6. 色阶/曲线 或 简化调整层
7. （可选）通道面板
8. （可选）钢笔/路径
```

## 风险（算法工程师视角）

- **选区 + 画笔 + 蒙版** 三者交叠：预乘 Alpha、软选区、蒙版乘算顺序一旦错，会出现脏边  
- **调整层** 若做成非破坏，合成管线复杂度明显上升；应用 OpenCV 做色阶/曲线可以，但要统一色彩空间  
- **钢笔** 对简历性价比偏低：时间更适合砸在蒙版与调整层演示链路上  
- CUDA：适合后期加速大图合成/滤波；**不要**在模型未稳前上 GPU  

---

## 结论

- **图层、选区、蒙版、画笔、（简化）调整层** → 是基础，且适合作为本项目主体。  
- **通道面板、钢笔路径** → 算「完整编辑器基础组件」，但对你当前目标偏重，建议后置。  
- 按推荐范围，代码量落在 **约 2～3.5 万行** 更健康；7 万是上限不是目标。
