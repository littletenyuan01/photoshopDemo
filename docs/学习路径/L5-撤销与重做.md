# L5 — 撤销与重做

**用户在干什么：** Ctrl+Z / Ctrl+Y，回到上一步编辑结果；也可以直接点历史面板里的任意一步。

**目标：** 说清 `HistoryStack`、Undo 条目类型、先 push 再改；**粒度与记账**决定内存与可撤深度；菜单/面板如何订阅。

**建议耗时：** 60～75 分钟（2026-10-15 扩容：新增粒度/记账/非线性三节）。  
**前置：** [L4](./L4-绘制操作.md)。

> ⚠️ **2026-10-15 按新实现更新**：撤销已从"整层深拷贝"改为**瓦片引用快照（TileRefs）**，并新增**历史面板 / 任意跳转 / 命名书签**。
> 本文旧版写的"不做 undo 瓦片化（C 档否掉）"**已被推翻**——原因与数字见 §2.3。

## 2. 代码落点

```text
ImageDocument
  └─ HistoryStack   push / undo / redo / jumpToStep / 书签 / 内存修剪
       UndoItem 种类：像素(LayerPixelsUndo) · 属性(LayerPropUndo) · 结构 ·
                      选区 · 路径 · 文档几何(DocumentGeomUndo)
changed → MainWindow 刷撤销菜单；HistoryPanel 刷历史列表
```

入口在 Document：`pushLayerPixelsUndo`、`pushSelectionUndo`、`pushPathUndo`…  
**铁律：先 push（改前快照），再改真相。**

### 2.1 两种「内存上限」，别混

| 机制 | 管什么 | 超限怎么办 |
|------|--------|------------|
| `HistoryStack` 字节上限（默认 ~256MB，`setByteLimit`） | **撤销条目** | 丢**最老** undo（可撤步数变少）；发 `historyTrimmed` |
| `TileCache`（`PSLITE_TILE_CACHE_MB`，默认 0=关） | **图层瓦片驻留** | 脏写 swap，干净直接丢内存副本；需要时再读回 |

push 之后也是静默点之一：`HistoryStack::push` 末尾可 `TileCache::trim`。

### 2.2 撤销条目现在有两种粒度

- **像素类默认 `TileRefs`（瓦片引用快照）**：`TileBuffer::takeRefSnapshot()` 只保存每块瓦片的 `QImage` **引用**（Qt 隐式共享），不拷像素。
- **谁先写谁 detach**：算子写瓦片走 `scanLine()`/`QImage::fill`，引用计数 >1 时 Qt 自动深拷贝那一块 ⇒ 快照自然保住旧内容（这就是 COW，`t_undocow` 用例钉住）。
- **必须显式 `WholeLayer` 的操作**：会改层 extent 的（更新链接、自由变换）——`pushLayerPixelsUndo(..., PixelUndoMode::WholeLayer)`。用错的症状：`pop` 里 extent 校验失败 → `qWarning` + Debug 断言 + 整层兜底。
- **出栈**：`swapWithRefSnapshot()` 做双向**交换**（不是写回）⇒ redo 对称；标脏按 `cacheKey` **差分**（只标真正变过的瓦片）+ 样式 `maxPadding()` 外扩。
- 深入：`domain/tilebuffer.*`（`TileRefSnapshot` / `swapWithRefSnapshot`）、`app/undoitem.cpp`（`LayerPixelsUndo::pop`、`changedTilesDocRect`）。

### 2.3 记账口径：**账面 ≠ 物理内存**（本层重点）

`HistoryStack` 按条目 `byteSize()` 之和与 256MB 比，**超了就丢最老**。所以"怎么算"直接决定可撤深度：

- 像素条目：按**触碰瓦片**计（`markDirty` 把触碰矩形交给栈顶条目）——不是按快照里全部引用算。
- 蒙版（属性类）：与图层**仍共享同一张**时**不计**（`m_maskShared`）；一旦被写而 detach 才按整张计。
- 蒙版**笔画**：每笔需要自己那一版快照，**物理上不可省**，只能靠记账准确。

2048² 实测（`pending-dev` 有完整表）：

| 场景 | 改造前 | 现在 |
|---|---|---|
| 满幅层画一笔 `undoBytes` | 16 777 280 | **16 512** |
| 200 笔历史峰值（1024² 稀疏） | ≈252 MB（触上限、反复 trim，深度被牺牲） | **25 600**（仅 0.02 MB，200 笔全留） |
| 200 笔历史峰值（2048²） | — | **7 398 400**（≈7.05 MB） |
| 撤销一次的重投影 | 整幅 2048×2048 | **64×64** |
| 带蒙版改 100 次显隐 | ≈100×4 MB | **28 400** |

**仍欠**：像素路径的蒙版捕获仍是深拷贝 ⇒ "层 + 蒙版 + 画像素"每笔仍 4 MB（见 [pending-dev](../pending-dev.md) **O6**）。

### 2.4 非线性：历史面板 / 跳转 / 书签

- **跳转 = 在双栈上重复 `undoOne/redoOne`**，外面包一层 `ImageDocument::ChangeBatch`：期间 6 类"变更类"信号只累计，最外层析构时按固定顺序补发一次 ⇒ **一次跳转只重投影一次**（否则 N 步 = N 次 `sync`）。为什么必须合并：`contentChanged` 在 `CanvasView` 里是**同步**调 `syncProjection()`。
- **书签 = 位置标记**（步号 + 名字），不是状态克隆；`trim` 丢掉最老 N 条后书签步号 `-= N`，指向已丢弃步的书签删除；新 push 会清 redo，同时删掉指向"未来步"的书签。
- 步号定义：总步数 `n = undo.size()+redo.size()`，游标 `c = undo.size()`；第 `i` 步名称：`i<c` 取 `undo[i]`，否则取 `redo[n-1-i]`。
- 深入：`app/historystack.cpp`（`jumpToStep` / `stepName` / 书签）、`ui/historypanel.*`、`domain/imagedocument.cpp`（`ChangeBatch` / `notify*`）。
- 计划与评估（想知道"为什么这么设计"就看这几份）：[undo-region-plan](../undo-region-plan.md)、[undo-nonlinear-plan](../undo-nonlinear-plan.md)、[undo-maskcost-plan](../undo-maskcost-plan.md)、[undo-region-review](../undo-region-review.md)、[undo-nonlinear-review](../undo-nonlinear-review.md)。
