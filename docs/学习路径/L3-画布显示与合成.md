# L3 — 画布显示与合成

**用户在干什么：** 盯着画布看图；缩放平移；期望一改图像屏幕就更新。

**目标：** 跟通脏区 → Projection 分块合成 → `QWidget::update`。

**建议耗时：** 60～90 分钟。  
**前置：** [L2](./L2-认识文档与图层.md)。

---

## 1. 工作流位置

```text
文档里已有图层像素
  → [本层] 合成后显示在画布
  → 下一层：用户动手绘制（会制造脏区，再走回本层刷新）
```

---

## 2. 代码落点

```text
doc->markDirty(rect) / contentChanged
  → CanvasView::syncProjection()
  → Projection::sync()
       → Compositor::compositeRegion(dst, doc, chunk)
       → 视口优先 + 时间预算；余量 idle 续算
  → update(局部)
  → paintEvent 画投影缓存 + 选区蚂蚁线等叠加
```

- **Compositor**：只读消费文档，不拥有图层。  
- **ViewPort**：工具用的视口抽象；生产实现 = `CanvasView`。  
- 选区变化常只重画蚂蚁线，**不必**整页重合成。

### 2.1 投影也占内存（且通常不能换出）

- `Projection::m_buffer` 是**整画布稠密**预乘图：要显示就必须在；页缓存**不会**把它当瓦片换走。  
- chunk 有效位可整片失效（压力下丢掉「可重算」派生状态，下次 sync 再算）。  
- 静默点：`Projection::sync` / `processPendingChunks` **之后**才可能 `TileCache::trim`（换页开启时）——绝不在合成中途扔正在读的瓦片。

---

## 2b. 补充 · 显示层几何与导航工具（2026-10 追加）

- **ViewPort 只管显示**：缩放/平移**不改任何数据**；坐标换算（`imageToWidget` / `widgetToImage`）在 `CanvasView`；每帧把可见区喂给 `Projection::setPriorityRect`——这就是"视口优先"的来源。
- **导航类工具**（`zoomtool` / `handtool`）**不压撤销**：它们不改文档真相（对照：绘制类改像素、几何类改 offset/extent、路径类改矢量）。
- 标尺与状态栏（`rulerwidget` / `canvasdocstatusbar`）读的是同一套换算，属"显示层"的消费者。
- 工具的五类分法与协议：见[工具框架专题](./专题-工具框架.md)。
