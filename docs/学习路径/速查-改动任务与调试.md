# 速查 — 按用户操作反查

## 用户动作 → 先看哪

| 用户动作 | 学习层 | 优先文件 |
|----------|--------|----------|
| 启动慢/起不来 | L1 / L11 | `main.cpp`、`RasterScheduler::warmUp` |
| 新建/打开不对 | L1 / L10 | `AppSession`、`MainWindow::openPath`、各 Io |
| 图层像素错 | L2 / L4 | `Layer`、`TileBuffer`、`PaintEngine` |
| 画了看不见 | L3 / L4 | `markDirty`、`Projection::sync`、`Compositor` |
| Ctrl+Z 无效 | L5 | `HistoryStack`、对应 `push*Undo` 时机 |
| 选区/蚂蚁线 | L6 | `Selection`、选区工具、`selectionChanged` |
| 透明度/排序/复制层 | L7 | `ImageDocument::setLayer*` / `duplicateLayer`、`sharePixelsFrom` |
| 滤镜效果 | L8 | `FilterStack`、`FilterEval`、`LayerFilterJob` |
| 钢笔/路径 | L9 | `PathStack`、`PenTool`、`patheditops` |
| 保存/导出 | L10 | `ProjectIo` / `RasterIo`；检查 `ProjectFormat` |
| 滤镜很慢/后端 | L11 | `RasterScheduler`、`rastercost` |
| **大图吃内存 / 想换页** | L2～L5 | `TileCache`、`PSLITE_TILE_CACHE_MB`、`PSLITE_MEM`；**统一导读** [内存专题 §6/§7](./专题-内存与预算地图.md)；设计与验收 [page-cache-plan](../page-cache-plan.md) |
| 历史动不动就丢 | L5 | `HistoryStack::byteLimit` / `historyTrimmed`（与瓦片换页不是一回事）；**先看记账口径**：像素看触碰瓦片、蒙版看是否仍共享（[L5](./L5-撤销与重做.md) §2.3） |
| 撤销后画面残留 / 没刷新 | L5 | 出栈标脏口径：`changedTilesDocRect` 的 cacheKey 差分 + 样式 `maxPadding` 外扩；`dirty` 为空时会回落整幅 |
| 点历史面板跳转很慢 / 面板不同步 | L5 | `jumpToStep` 是否包了 `ChangeBatch`？补发顺序与 `m_pending*` 是否漏项（用例 `t_undobatch` / `t_undojump`） |

## 现象 → 排查顺序

| 现象 | 顺序 |
|------|------|
| 换文档面板不刷新 | 是否订 `documentChanged`；裸指针是否仍指旧 doc |
| 只局部花屏 | dirty 矩形坐标系（层 vs 文档）；Projection chunk |
| 打开工程失败 | Format 是否等于 `Current`；魔数 `PSLT` |
| 无显卡无法用 | 不应；查是否错误强制 GPU、探测是否挡住启动 |
| 复制图层后内存翻倍 | 是否误走 `materialize`；应 `sharePixelsFrom`（L7） |
| 开了换页仍崩 / 花屏 | 是否在 `ensureTile` 路径淘汰；静默点是否只在 sync/抬笔/push；并行读时是否少了 `TileSharedReadGuard`（[并发专题 §3.2](./专题-并发与线程安全.md)） |

## 断点建议

`AppSession::setDocument` → `markDirty` → `Projection::sync` → `ToolManager::dispatchPress` → `ProjectIo::load/save` →（可选）`TileCache::trim`
