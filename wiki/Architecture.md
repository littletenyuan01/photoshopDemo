# 架构设计

借鉴 GIMP 的**分层**，用更小的体量在 Qt 中实现。

## 推荐模块（计划）

```text
┌─────────────────────────────────────────┐
│  UI（Qt）                                │
│  MainWindow / Canvas / LayerPanel / Tools│
├─────────────────────────────────────────┤
│  Tools                                   │
│  交互：指针事件 → 调用 Paint / 命令      │
├─────────────────────────────────────────┤
│  Document / Layers                       │
│  图像文档、图层列表、活动层、合成        │
├─────────────────────────────────────────┤
│  Paint / Pixel ops                       │
│  笔触写入图层缓冲                        │
├─────────────────────────────────────────┤
│  History（Undo / Redo）                  │
│  命令或快照栈                            │
├─────────────────────────────────────────┤
│  IO                                      │
│  打开 / 导出                             │
└─────────────────────────────────────────┘
```

## 与 GIMP 的对应（学习用，非抄代码）

| GIMP | 本项目简化对应 |
|------|----------------|
| `app/core` 图层与 drawable | Document + Layer（可用 `QImage` 作像素缓冲） |
| `app/paint` vs `app/tools` | Paint 算法 与 Tool UI/事件 分开 |
| GEGL 合成图 | v1 用 CPU 逐层合成到一张预览图即可 |
| PDB / 插件 | **不做** |

## 设计原则

1. **UI 不拥有核心数据**：窗口只展示与发命令  
2. **工具不直接乱改全局**：通过 Document / 命令写入  
3. **合成可替换**：先简单实现，接口保持清晰  
4. **控制行数**：少抽象、少框架，优先可演示
